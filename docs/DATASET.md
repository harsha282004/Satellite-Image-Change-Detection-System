## Primary dataset: LEVIR-CD

### Source of truth
- **Original/official dataset:** LEVIR-CD (Chen & Shi, 2020), *"A Spatial-Temporal Attention-Based
  Method and a New Dataset for Remote Sensing Image Change Detection"*, Remote Sensing, 12(10):1662.
- **Official project page:** https://justchenhao.github.io/LEVIR/
- **Official download links (manual only):**
  - Google Drive: `drive.google.com/open?id=1dLuzldMRmbBNKPpUkX8Z53hi6NHLrWim`
  - Baidu Drive: `pan.baidu.com/s/1fzNiOE7elGRmIo2h6MIhZw` (code: `l7iv`)

  Both official links are interactive cloud-drive folders (Google Drive / Baidu Netdisk). Neither
  exposes a stable, unauthenticated direct-download URL suitable for unattended scripted download,
  and Google Drive in particular gates large files behind a browser virus-scan-warning /
  confirmation click. Per `DEVELOPMENT_RULES.md` (stop conditions), this was **not** used for
  automated acquisition — a reliable programmatic alternative was used instead (see below), and this
  is documented rather than silently substituted.

### Actual acquisition source used
- **Mirror:** Hugging Face dataset repo `satellite-image-deep-learning/LEVIR-CD`
  (https://huggingface.co/datasets/satellite-image-deep-learning/LEVIR-CD)
- **This is a distribution mirror, not the original source.** It is documented here as such per
  `PROJECT_CONTEXT.md`'s dataset acquisition rules. The underlying dataset is LEVIR-CD as described
  above; citation obligations are to Chen & Shi (2020), not to the mirror.
- **Why this mirror:** it exposes the dataset as plain, stable, individually-addressable files
  (`train.zip`, `val.zip`, `test.zip`, plus a separate `LEVIR-CD+.zip` for the larger LEVIR-CD+
  variant, which is **not** used here) downloadable via the `huggingface_hub` Python client with no
  authentication, resumable transfer, and file-level integrity metadata — i.e. a reliable
  programmatic download, unlike the official Google Drive / Baidu links.

## Dataset composition (as documented by the official source)
- 637 bitemporal image patch pairs
- Image size: 1024 × 1024 pixels, very-high-resolution (0.5 m/pixel), from Google Earth
- Temporal span: 5–14 years between the two images in a pair (imagery from 2002–2018)
- 31,333 individually annotated building-change instances
- 20 regions across several Texas cities (Austin, Lakeway, Bee Cave, Buda, Kyle, Manor,
  Pflugerville, Dripping Springs, etc.)
- Ground truth: binary building-change mask per pair (change / no-change)

## Data structure (paired samples)
Each split (`train` / `val` / `test`) is expected to contain matched triplets:
```
<split>/A/<name>.png      # before image
<split>/B/<name>.png      # after image
<split>/label/<name>.png  # binary change mask
```
This is verified against the actually-extracted files below, not assumed.

## Leakage prevention / split methodology
The train/val/test split used is the **official LEVIR-CD split** as provided by the dataset
authors (downloaded as separate `train.zip` / `val.zip` / `test.zip` archives, not re-split here).
Splits are geographically pre-partitioned by the original authors; this project does not merge and
re-shuffle the splits, which would risk leaking near-duplicate/geographically-overlapping tiles
across train and test. If any custom re-splitting is ever introduced later, it will be documented
here explicitly with the methodology used to avoid geographic leakage.

### Mask binarization note
Ground-truth mask pixel values observed across sampled files are **not perfectly binary**: most
files contain only `{0, 255}`, but some contain intermediate values such as `156` or `254`
(anti-aliased mask edges), i.e. value sets like `{0, 156, 255}` or `{0, 254, 255}`. Preprocessing
(Phase 3) must explicitly threshold masks (e.g. `> 127`) to binary `{0, 1}` rather than assuming
raw pixel values are already exactly binary.
